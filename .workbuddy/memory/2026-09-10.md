## 2. 结清 WorkBuddy 签到遗留项（checkin平台全流程方案.md → v1.2）

- **鉴权**：Bearer **仅需 `Authorization` 头**（`X-User-Id`/`X-Device-Token`/`X-Domain` 实测非必需）。

### 6.2 ★ 设备指纹 fp 算法（逐字节验证通过）
```
serialized = "&".join(f"{quote(k)}={quote(v)}" for k,v in sorted(fields))   # 空值也要保留
body       = serialized + "&cs=" + SHA1(serialized)      # ★SHA1，不是 MD5
fp         = base64( XOR(body).encode('latin-1') )        # key 初值 211，key ← 密文字节
```
- **`cs` 必须 SHA1**：改用 MD5（云空间旧版算法）→ 服务端 200 但 `sid` 返回**空串**。
- **服务端不校验各哈希字段真实性**：canvas/webgl/fonts/ep/epls 全换伪造值，只要 `cs` 对，照样签发 sid
  ⇒ **纯 Python 即可，不需要 Playwright**（这点比参考项目更省事）。
- **两个坑**：① XOR 加密/解密是**两个不同函数**（都按密文字节滚动 key），不互为自反；
  ② XOR 输出必须 `.encode('latin-1')` 再 Base64，用 utf-8 会把 744 撑到 928 并被判非法。

### 6.3 ★ hwid_cas_sid = 免验证的持久化关键
- 请求带已有值 → 服务端**原样回显**并写 `Max-Age=315360000`（10 年）cookie。
- 不带 → 每次会话新签发一个 sid（同会话幂等、跨会话不同）。
⇒ 持久化它，后续重登自带受信设备身份，**不会再触发设备验证**。这是解决"没有持续 cookie"的正解。
