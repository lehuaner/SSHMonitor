## checkin「预估可用天数」功能（前后端新增）
任务：在 checkin 数据面板新增"预估可用天数"，公式 `剩余可用积分 / (平均每日使用积分 - 平均每日签到积分)`，分别展示每个账号与总账号。

- 后端源码在本地 `D:\Code\Project\SSH\Honor 10\monitor\`，部署到远程 Termux `$HOME/monitor`（用 ssh mcp 上传）；前端 `monitor/frontend/*.html` 是静态站，部署在 Cloudflare Pages（项目 `honor10-monitor`，用 `deploy-pages.ps1`）。
- 关键实现点：
  - 复用 `getUsageStats()`（已有 avgDailyConsumption）+ `getTotalCreditsForTask(id)`（一次实时调用返回 `{total, checkins}`，同时拿到剩余积分与每日签到记录）。
  - 新增 `lib/checkin-stats.js` 的 `getUsageStatsWithEstimates()`；`server.js` 的 `/api/checkin/stats` 改为 `await getUsageStatsWithEstimates()`。
  - **平均每日签到积分分母只算有签到的天数（credits>0），不把 0 签到日计入**——用户特别强调。
  - 分母为0/负 → 标记「充足」；缺数据 → null；数值保留1位小数。
  - 总账号口径：`Σ剩余 / Σ(各账号净日耗)`。
- 前端 `frontend/checkin.html` renderStats() 新增 `fmtEst(v)`：null→`—`、'充足'→'充足'、否则 `X.X 天`；并加「预估可用天数(总)」卡片 + 每账号行追加预估天数。

注：初版用 `avgDailyConsumption`（含无消耗日稀释的毛日均）作分母，导致 使用(75)−签到(200)<0 误显示「充足」。

## 修正1：分母改用「净日均」(netDailyAvgConsumption)
用户指出：公式「平均每日使用积分」应该用前端展示的"净日均" `netDailyAvgConsumption`（有消耗记录日的日均，来自 checkin_stats.json 快照聚合 `sumC/netCDays`），而非被稀释的 `avgDailyConsumption`。
修正后 `剩余/(净日均−签到)` → 账号1≈0.45天、账号2≈0.61天，不再"充足"。账号3 无消耗记录(net日均=null)仍显示 `—`。

## 修正2：总账号 null 当 0 + 新增「10天尺度」
- 总账号汇总时，单账号净日均=null 按 0 计（用户："null就是0可以计算，不算失真"），剩余照常计入。总预估=3.43天（含账号3的4700）。
- 新增"10天尺度"：除全窗口净日均外，再用 `getUsageStats()` 返回的 `a.days` / `total.byDate` 取**近10天有消耗日**的净日均，算第二个预估天数 `estimatedDays10d`。
  - 后端 `getUsageStatsWithEstimates(checkinDays=30, recentDays=10)`：新增 `netDailyLastN(days,n)` 取近N天有消耗日均值；签到也分全/10天两套均值。
  - 字段：账号 `estimatedDays`/`estimatedDays10d`/`avgDailyCheckin10d`；总 `estimatedDays`/`estimatedDays10d`/`avgDailyCheckin10d`/`netDailyAvgConsumption10d`。
  - 前端：#statsTotal 加「预估可用天数(总·近10天)」卡片；每账号行 `预估 X天 (近10天 Y天)`。
  - 验证：账号2 全0.61天 vs 近10天4.20天（近期消耗变慢）；总 全3.43天 vs 近10天9.21天。
- 部署：后端 ssh 上传+自动重启；前端 `deploy-pages.ps1`（Cloudflare Pages 项目 honor10-monitor）已上线验证含 `estimatedDays10d`。
