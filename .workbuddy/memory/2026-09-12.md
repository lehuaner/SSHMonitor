## 1. ★ CodeArts 17327137416「凭证有效但签到失败」——根因定位与修复

**现象**：09-12 00:02 起签到失败，`lastError="领取失败（claim 返回 false）"`、`failCount=2`，
但 `credentialTest/status/credits/usage` 全部正常（余额 8355.28 可读）。

### 根因（一句话）
上游把「每日签到」从 `/portal/snap-manager/v1/credit/*` 迁到**运营活动中心**
`/portal/promptcenter/v1/ops/*`；**旧路由保留但已不服务，改为返回 HTTP 200 + 完全空响应体**。
客户端仍调旧接口，旧实现 `r.data !== null ? r.data : /true/i.test(r.text)` 把空体判成 `false`
⇒ 同时得出「今天没领过」和「领取失败」两个错误结论。

### 定位链路（结论性证据）
| 实验 | 结果 | 排除了什么 |

| 最小 cookie 集 / 去 `cftk` 头 / 加 `origin`+`sec-fetch-*` / 换 body | 全空体 | 请求头、参数、CSRF |
| 冒烟 `GET /credit/__nope__` → `400 TM.00001001` | 失败路径是**注册过的** | 路由缺失 |
| 抓前端 bundle 版本 126.8.310 → **126.9.107**，`grep credit/claim` = **0 次** | 前端已弃用 | —— |

## 3. 顺手记下的环境事实
- monitor 由 runit 托管，**服务名是 `server`**（不是 `monitor`）：`sv status server`；
  `deploy-remote.sh` 内部做 `sv restart server` + 清理非 runsv 托管的孤儿实例。
- ssh-mcp 的 upload 会**吞掉源码里的反斜杠转义**（`'\n'` 变真实换行），写探针务必避开 `\n`。
- **大文件/易被转义的内容走 base64 中转**：本地 `base64` → 上传纯 ASCII 的 `.b64` →
  远端 `base64 -d` → **两边 `sha256sum` 对拍**。`.b64` 里没有反斜杠，天然免疫该问题。
- **改远端代码前先把它拉下来 diff**：本次本地文件比远端大 7KB（本地有未部署改动），
  直接覆盖会静默回退。用 `difflib.unified_diff` 确认「远端独有行」全是本次要删的旧代码再覆盖。
- 抓包里的 `fp` 可用 `examples/_decode_hwmeta.py`（XOR 滚动密钥 211）解出明文；
  但 **`hwmeta` 解不出**（是 accountguard 风控 SDK 的二进制 TLV，非同一算法）——
  不过实测 `hwmeta=''` 也被服务端接受，**不要为此去逆向**。
